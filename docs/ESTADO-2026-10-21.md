## 7. Instalação da leva 1 (depois das 14:00 de 21/10, com o REAL desligado)

`/etc/kalman-ordens/pnt-md-hml.env` não existe (`EnvironmentFile=-`) e não há `PNT_MD_TOKEN` em lugar
nenhum (conferido pelo usuário): vale o caminho padrão do código, `/var/lib/kalman-pnt-md-hml/token.json`.

```
sudo systemctl stop kalman-pnt-md-hml
cd ~/kalman-ordens && git pull && git merge --ff-only pnt-md-v4     # (ou o merge feito aqui)
sudo install -o root -g root -m 644 deploy/kalman-pnt-md-hml.service /etc/systemd/system/kalman-pnt-md-hml.service
sudo install -d -o gammaquant -g gammaquant -m 700 /var/lib/kalman-pnt-md-hml
install -m 600 ~/.config/pnt-md-spike/token.json /var/lib/kalman-pnt-md-hml/token.json
sudo systemctl daemon-reload && sudo systemctl start kalman-pnt-md-hml
curl -s 127.0.0.1:9096/saude                                     # token_ok, book_ok, reconexoes_book 0
curl -s -X POST 127.0.0.1:9096/reconectar; sleep 10; curl -s 127.0.0.1:9096/saude   # close_servidor {code: 1000}
rm ~/.config/pnt-md-spike/token.json                             # depois de token_ok
```

O drop-in `selinux.conf` continua (o `ExecStart` dele não muda). Depois da instalação, a regra das
09:00 vira reserva: a reconexão automática cobre a conexão aberta antes do pré-abertura.
